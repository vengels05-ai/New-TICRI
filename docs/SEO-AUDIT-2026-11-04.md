# TICRI search discovery audit — November 4, 2026

The site has a useful foundation: readable educational content, descriptive topic URLs, and internal navigation that works without relying on a search engine to operate the interactive tools. The largest technical gaps were repeated page metadata, a missing sitemap, and no declared canonical URLs. Those gaps are fixed in this checkout. **The changes still need deployment before they affect the live website.**

## Evidence and scope

Reviewed the Next.js routes and the exported HTML for all 325 public pages, excluding the two generated error pages. Also fetched the live homepage, First Amendment page, Marbury v. Madison page, an opinion reader, robots.txt, sitemap.xml, and the HTTP/www host variants.

| Check | Before this change | Local implementation |
| --- | --- | --- |
| Titles | 319 public pages shared the site-wide title | Separate titles for all public pages, including all 50 states |
| Descriptions | Only 7 distinct descriptions across public pages | Separate descriptions drawn from each page’s content |
| Canonical URLs | None in the export or sampled live pages | HTTPS, non-www URLs with the trailing slash used by this site |
| Sitemap | Live `/sitemap.xml` returned HTTP 404 | Generated sitemap for 319 indexable pages |
| robots.txt | Live file contained hosting-managed explanatory comments, without a sitemap declaration | Explicit crawl permission and sitemap location |
| Structured data | None in the export or sampled live pages | Homepage `WebSite` and `Organization` JSON-LD |
| Social sharing | Most pages inherited the homepage title, description, and URL | Per-page Open Graph and Twitter metadata |
| Internal links | Acts directory linked to nonexistent `/acts/patriot-act-2001/` | Corrected to `/acts/usa-patriot-act-2001/` |

The existing logo is 1024 × 1024. Its sharing metadata previously claimed 1200 × 630; the dimensions now match the actual image.

The source changes move 37 existing client pages into adjacent `PageClient.tsx` files so server page wrappers can export metadata. Their component source is preserved, with the one broken link correction above.

## Deliberately excluded pages

Six routes now use `noindex, follow` and are omitted from the sitemap:

- `/acts/bill/`, `/cases/opinion/`, `/executive-orders/order/`, and `/us-code/section/` are generic readers requiring query parameters. Their initial HTML does not identify a specific document. This exclusion also applies to their query variants until record-specific rendering is implemented.
- `/acts/index/` is a largely empty legacy page.
- `/truth-and-law/` is a coming-soon page.

These pages remain accessible to visitors. Their exclusion concentrates indexing on completed educational material. Before enabling indexing for the readers, give each record a stable URL, meaningful rendered content, and its own title, description, and canonical URL. For example, an individual case should have a distinct document URL rather than sharing a generic reader’s metadata. This is the largest remaining engineering opportunity for discovery of the live collections.

## Next steps, in order

1. **Deploy this checkout.** Verify that `https://ticri.org/sitemap.xml` and `https://ticri.org/robots.txt` return the new files. Check the public response because the hosting layer currently manages part of robots.txt.
2. **Redirect the www host to the preferred non-www host.** The live `https://www.ticri.org/` returned HTTP 200 at its own address rather than redirecting. Canonical tags now express the preference, but a permanent host redirect would reinforce it. HTTP already redirected to HTTPS in the sampled request. Preserve paths and query strings when configuring the host redirect. [Google’s canonicalization guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) covers these signals.
3. **Verify ownership in Google Search Console and Bing Webmaster Tools, then submit the sitemap.** Search Console access was not available during this audit, so actual index coverage, rankings, and search traffic have not been established. Use [Google’s Sitemaps report](https://support.google.com/webmasters/answer/7451001) and [Bing’s sitemap submission](https://www2.bing.com/webmasters/help/sitemaps-3b5cf6ed).
4. **Inspect representative pages after deployment.** Start with the homepage, First Amendment, Marbury v. Madison, a state constitution, and an Acts page. Confirm that Google can fetch the content and recognizes the intended canonical. [URL Inspection](https://support.google.com/webmasters/answer/9012289/) shows index status and supports live-page tests.
5. **Add record-specific rendered URLs for live collections.** Start with a curated set of useful cases or laws. Include only real, available records in their sitemaps, and return an actual 404 for nonexistent records. Expanding to every database row should follow checks for source coverage, useful content, and build/hosting limits.
6. **Strengthen content trust and usefulness.** For legal and constitutional explainers, make primary sources, authorship/review responsibility, substantive update dates, and the distinction between historical decisions and current law clear to readers. The About page already establishes the project and founder. This audit did not substantively fact-check every legal explanation. [Google’s helpful-content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) explains the role of clear sourcing and demonstrable expertise.
7. **Measure discovery and use.** Track Search Console impressions, clicks, queries, and landing pages. Start with topic clusters such as “First Amendment explained,” “how Congress works,” and individual state constitutions; use actual query data to refine page content and links. Track whether visitors continue into related explainers or primary-source readers, using an appropriate privacy-conscious measurement approach. Analytics installation and a mobile performance audit remain separate work.

A sitemap helps discovery but does not guarantee indexing or ranking. Helpful, accurate pages and relevant links from other sites remain necessary alongside these technical fixes. [Google’s SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) explains the broader work.

## Verification and maintenance

- Final production build and SEO audit passed: 325 public pages, 319 indexable sitemap entries, and 6 excluded readers/placeholders. The export also passed the hosting asset limits.
- `npm run build` exports the static site and automatically runs asset-limit and SEO checks.
- `npm run seo:audit` checks the existing export independently. It validates titles, descriptions, duplicate metadata, canonicals, social metadata, headings, sitemap coverage, homepage structured data, and internal link targets.
- TypeScript and targeted lint checks passed.
- All 9 content/export regression tests passed. The broader `npm test` run had 32 passing tests, 1 skipped test, and 5 API-contract failures because the local Congress Worker was not running at `127.0.0.1:8787`.
- Source comparison confirmed all 37 extracted client components preserve the original code, apart from the corrected Acts link.

For a new page, export metadata with `createPageMetadata` from `lib/seo.ts`. Static pages are discovered automatically by the sitemap; new dynamic route families need their own parameter expansion. Add pages to `NON_INDEXABLE_PATHS` only when they should intentionally stay out of search. Do not substitute build timestamps for genuine content update dates.
